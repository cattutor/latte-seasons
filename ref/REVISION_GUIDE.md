## ■ SECTION A: 피하수액 시스템 전면 교체

### A-1. 의학적 배경 (개발자 필독)

현재 GDD와 코드 전반에서 수액을 **정맥주사(IV)**로 묘사하고 있으나, 이는 의학적 오류다. 말기 신부전 고양이의 재택 수액은 **피하수액(Subcutaneous Fluid Therapy)**이며, 시술 방식이 완전히 다르다.

**피하수액의 실제 과정:**

1. **준비**: 링거액(Lactated Ringer's 또는 생리식염수) 백을 **뜨거운 물에 중탕**하여 체온(38~39℃) 정도로 데운다. 전자레인지는 절대 사용하지 않는다—수액이 불균일하게 가열되거나 성분이 변성될 수 있다. 차가운 수액은 고양이에게 불쾌감을 준다.
2. **자세**: 고양이를 부드러운 표면(이불, 무릎) 위에 엎드리게 한다. 긴장하지 않도록 간식이나 쓰다듬기로 주의를 분산시킨다.
3. **피부 잡기**: 등 쪽 견갑골(어깨뼈) 사이의 피부를 엄지와 검지로 **텐트 모양**으로 잡아 올린다. 피부가 늘어나며 피하 공간이 만들어진다.
4. **삽입**: 18~20G 나비 바늘(butterfly needle)을 텐트 밑부분에 비스듬히(약 45도) 삽입한다. 정맥을 찾을 필요 없이 피하 공간에만 닿으면 된다.
5. **주입**: 클램프를 열어 수액을 중력으로 천천히 흘려보낸다. 100~150ml를 약 5~10분에 걸쳐 주입한다.
6. **수액 혹**: 주입이 진행되면 등에 수액이 **혹처럼 볼록하게** 부풀어 오른다. 처음 보는 사람은 놀라지만 정상이다. 수 시간에 걸쳐 몸이 흡수한다.
7. **마무리**: 바늘을 빼고 삽입 부위를 손가락으로 잠시 누른다. 라떼의 등을 부드럽게 쓸어준다.

**감정적 핵심**: 정맥주사의 "정확한 혈관에 바늘을 꽂는 기술적 긴장"이 아니라, "내 손으로 아이의 피부를 잡아 올려야 하는 심리적 무게"가 핵심이다. 날이 갈수록 라떼의 피부가 탈수로 탄력을 잃어 텐트가 잘 안 만들어지고, 이전에 찔렀던 자리가 딱딱해져 새 자리를 찾아야 한다.

### A-3. 미니게임 재설계 — "피하수액 놓기"

**기존 `runIVMinigame()` 전면 교체.**

**게임플레이 흐름 (2단계 구성):**

```
[Phase 1: 피부 잡기]
  화면: 라떼 등의 픽셀 확대 뷰 (견갑골 사이 영역 표시)
  인터랙션: 좌우로 움직이는 "잡기 커서"가 있다.
            녹색 구간(견갑골 사이)에서 홀드(꾹 누르기)하면 텐트 형성.
            홀드 시간이 짧으면 텐트 불완전 → Phase 2 난이도 상승.
  연출: 홀드 중 라떼 스프라이트가 미세하게 움찔함.

[Phase 2: 바늘 삽입]
  화면: 텐트가 형성된 피부의 단면 뷰 (간략화된 도식)
  인터랙션: 타이밍 바가 좌우로 이동. Safe Zone에서 클릭.
  난이도: Phase 1의 텐트 품질에 따라 Safe Zone 크기 변동.
  연출:
    Perfect → "바늘이 부드럽게 들어갔다." + 수액 주입 애니메이션 (등이 볼록해짐)
    Good → "살짝 움찔했지만 괜찮다."
    Miss → "라떼가 몸을 비틀었다." + 화면 흔들림 + 재시도 없음 (결과 확정)
```

**난이도 곡선:**

| 챕터 | 피부 탄력 | 텐트 유지 시간 | Safe Zone 폭 | 감정 키워드 |
|------|-----------|---------------|-------------|------------|
| Ch.1 | 양호 | 길다 | 넓음 (~20%) | "처음이라 떨리지만 할 수 있다" |
| Ch.2 | 저하 | 보통 | 보통 (~14%) | "어제보다 피부가 푸석하다" |
| Ch.3 | 많이 저하 | 짧다 | 좁음 (~10%) | "다른 자리를 찾아야 한다" |
| Ch.4 | 극심 | 매우 짧다 | 매우 좁음 (~7%) | "찌르는 게 맞는 건지 모르겠다" |

**결과 Delta (기존 대비 조정):**

```javascript
// Perfect
{ hp: 4, comfort: 3, sanity: 1, money: -2, bond: 2 }
// Good  
{ hp: 3, comfort: 1, sanity: 0, money: -2, bond: 1 }
// Miss
{ hp: 1, comfort: -3, sanity: -3, money: -2, bond: -1 }
```

## ■ SECTION B: 엔딩 시스템 재구축

### B-1. 엔딩 4분기 체계 (GDD 정합)

**기존 `triggerEnding()` 전면 교체.**

```javascript
function triggerEnding() {
  if (state.ended) return;
  state.ended = true;

  const { hp, comfort, bond, hiddenPoint, sanity } = state;

  if (hiddenPoint >= 5 && bond >= 70 && comfort >= 60) {
    // Hidden Ending: 무지개 다리
    state.ending = {
      code: "Rainbow",
      title: "무지개 다리",
      text: "모든 기억이 꽃이 되어 흩날린다. 라떼가 초원을 달린다."
    };
  } else if (comfort >= 70 && bond >= 60) {
    // Ending A: 나의 라떼
    state.ending = {
      code: "MyLatte",
      title: "나의 라떼",
      text: "19스푼의 기적 이후, 라떼는 꿈결처럼 떠났다. 표정은 편안했다."
    };
  } else if (hp >= 40 && sanity >= 40) {
    // Ending B: 병원에서의 사투
    state.ending = {
      code: "Fighter",
      title: "병원에서의 사투",
      text: "끝까지 포기하지 않았다. 병원의 형광등 아래, 조금 더 긴 시간을 함께했다."
    };
  } else {
    // Ending C: 자연의 섭리
    state.ending = {
      code: "Nature",
      title: "자연의 섭리",
      text: "창문 너머로 새벽빛이 들어온다. 라떼는 집에서, 익숙한 이불 위에서, 자연스럽게 잠들었다."
    };
  }

  // ... 이후 연출 로직 동일
}
```

### B-2. 엔딩 철학 지침

> **"이 게임에 Bad Ending은 없다."**

모든 엔딩 텍스트는 다음 원칙을 따라야 한다:

1. **플레이어를 비난하지 않는다.** "회한", "실패", "후회" 같은 단어를 엔딩 이름이나 본문에 사용하지 않는다.
2. **모든 결말은 사랑의 다른 형태다.** Ending A는 "충분히 교감한 이별", B는 "끝까지 싸운 이별", C는 "자연에 맡긴 이별", Hidden은 "모든 기억을 꽃으로 되돌려주는 이별"이다.
3. **엔딩 후 텍스트에 반드시 포함할 문장:** `"어떤 선택을 하든, 당신은 좋은 보호자였습니다."`

### B-3. 엔딩별 특전 (2회차 연동)

| 엔딩 | 특전 | 구현 |
|------|------|------|
| A 나의 라떼 | 라떼의 일지 Full ver. 해금 | `localStorage.setItem('ending_A', true)` |
| B 병원에서의 사투 | 수의 기록 모드 해금 | `localStorage.setItem('ending_B', true)` |
| C 자연의 섭리 | 조용한 방 BGM 해금 | `localStorage.setItem('ending_C', true)` |
| Hidden 무지개 다리 | Prologue 후일담 해금 | `localStorage.setItem('ending_H', true)` |

## ■ SECTION C: 이벤트 반복 해소 — 일자별 텍스트 시스템

### C-1. 구조 변경: `EVENTS` → `EVENTS` + `DAY_TEXTS`

현재 `EVENTS[chapter][slot]`은 챕터당 5개(슬롯별 1개)뿐이다. 7일 × 5턴 = 35턴 동안 같은 텍스트가 반복된다. 이를 해소하기 위해 **일자별 텍스트 레이어**를 추가한다.

```javascript
// 기존 EVENTS 구조는 유지하되, 선택지/delta의 "기본값" 역할로 전환.
// DAY_TEXTS가 해당 일자에 존재하면 텍스트와 cue를 오버라이드.

const DAY_TEXTS = {
  // key: "day-slot" 형식
  "1-0": { cue: "첫 새벽", text: "뜨거운 물에 링거백을 담가 체온만큼 데운다. 차가우면 라떼가 싫어한다. 등의 피부를 처음 잡아 올리는 손이 떨린다." },
  "1-1": { cue: "첫 출근", text: "어제 수의사에게 들은 말이 머릿속을 맴돈다. 출근길 지하철에서 검색한다. '고양이 신부전 생존율.'" },
  "1-2": { cue: "CCTV 설치", text: "카메라를 설치했다. 흑백 화면 속 라떼가 이불 위에 웅크려 있다. 살아 있다. 숨을 쉰다." },
  // ... 28일 × 5슬롯 = 최대 140개 (필수: 최소 챕터당 14개)
};

function getEventForDay(day, slot) {
  const chapter = day <= 7 ? 1 : day <= 14 ? 2 : day <= 21 ? 3 : 4;
  const base = EVENTS[chapter].find(e => e.slot === slot) || EVENTS[chapter][0];
  const dayKey = `${day}-${slot}`;
  const override = DAY_TEXTS[dayKey];

  const scene = {
    cue: override?.cue || base.cue,
    text: override?.text || base.text,
    choices: base.choices.map(c => ({ ...c, delta: { ...c.delta } })),
    // ... 기존 accessories 로직 유지
  };
  return scene;
}
```

## ■ SECTION D: 선택지 트레이드오프 재밸런싱

### D-1. 문제 진단

현재 일부 선택지가 "명확히 나쁜 선택"으로 설계되어 있다. 예: Ch.1 새벽 "빠르게 끝내기"(HP+2, Comfort-2, Sanity-3, Bond-1) — 모든 수치가 열등하여 선택할 이유가 없다.

### D-2. 원칙

> **"모든 선택은 무언가를 포기한다."**

각 선택지는 반드시 **하나 이상의 장점**을 가져야 한다. 어떤 선택이든 보호자로서의 합리적인 이유가 있어야 한다.

### D-3. 수정 예시

**Ch.1 새벽 (slot 0) — 수액:**

```
기존:
  1. 천천히 수액       → HP+5, Comfort+2, Sanity-1, Money-2, Bond+2  (최선)
  2. 빠르게 끝내기      → HP+2, Comfort-2, Sanity-3, Money-1, Bond-1  (열등)
  3. 잠시 안아주고 재시도 → HP+3, Comfort+4, Sanity 0, Money-2, Bond+3  (차선)

수정 (트레이드오프 강화):
  1. "등을 충분히 데워주고 천천히"
     → HP+4, Comfort+3, Sanity-2, Money-2, Bond+2
     장점: 체력/편안함 최대. 단점: 시간이 오래 걸려 보호자 소진.
  
  2. "최대한 빠르게 끝내기"
     → HP+3, Comfort-1, Sanity+2, Money-1, Bond 0
     장점: 보호자 멘탈 보존 (Sanity+2). 단점: 라떼 편안함 저하.
     이유: "빠르게 끝내서 서로 스트레스를 줄이자"는 합리적 판단.
  
  3. "잠시 안아서 긴장을 풀어주고 재시도"
     → HP+2, Comfort+4, Sanity-1, Money-3, Bond+3
     장점: 교감/편안함 최대. 단점: 시간 소모로 돈 추가 지출, 체력 회복 최저.
     이유: 효율보다 교감을 택한 선택.
```

**Ch.1 저녁 (slot 3) — 급여:**

```
기존:
  강제 급여 → HP+5, Comfort-4, Sanity-3, Money-1, Bond-2  ("나쁜 선택"처럼 보임)

수정:
  "강제 급여 (시린지 피딩)"
     → HP+5, Comfort-2, Sanity-2, Money-1, Bond-1
     장점: HP 회복 최대 — 생존에 직결. 단점: 교감/편안함 저하.
     이유: "먹어야 살 수 있다"는 의학적으로 옳은 판단. 나쁜 선택이 아니다.
```

### D-4. 전체 밸런싱 규칙

모든 선택지 delta를 검토할 때 다음 규칙을 적용한다:

1. **어떤 선택지든 3개 이상의 자원이 동시에 마이너스면 안 된다.**
2. **모든 선택지는 최소 하나의 자원에서 최고값을 가져야 한다.** (그 선택을 골라야 하는 이유)
3. **"체력 vs 편안함 vs 멘탈" 삼각 트레이드오프**를 기본 축으로 한다.
4. **Bond는 "효율을 포기하고 교감을 선택했을 때" 보상으로 준다.** 가장 효율적인 선택에 Bond가 높으면 안 된다.

```javascript
function launchChoiceInteraction(choice, scene) {
  // CCTV 미니게임: 출근한 날의 오후에만
  if (scene.cue.includes("CCTV") && state.timeSlot === 2 && state.todayCommuted) {
    return runCCTVMinigame(choice, scene);
  }
  // 급여 미니게임: 저녁(slot 3)의 강제 급여만
  if (choice.key === "forceFeed" && state.timeSlot === 3) {
    return runFeedMinigame(choice, scene);
  }
  // 수액 미니게임: 새벽(slot 0) 전용 — 오전(slot 1) 제거
  if (choice.label.includes("수액") && state.timeSlot === 0) {

  }
  return chooseAction(choice, scene);
}
```
